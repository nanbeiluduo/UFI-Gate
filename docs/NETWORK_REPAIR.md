# 热点接口与网关检测、校验及修复（待发布）

本功能基于 1.1.9 开发，尚未分配发布版本。需要同时更新 Go 服务、service.sh 和对应架构的 JS 插件。只更新后台服务不会替换 UFI-TOOLS 保存的插件菜单。

## F50 问题与操作

中兴 F50 的热点侧 `192.168.0.1/24`、手机 ARP 和邻居记录位于 `br0`，如果保存配置却为 `wlan0`，管理员初始化可能无法识别设备。重新连接手机、只修改安装器输入或 bootstrap.json，不会覆盖已有 state.json。

1. 在 UFI-TOOLS 插件打开「检测环境」。程序显示实际运行、保存状态、安装引导三组配置，以及系统接口、UP/DOWN、IPv4/前缀和候选理由。
2. 首次安装时核对推荐接口和热点侧地址。安装会重新校验，明确不匹配会阻止安装。已有状态保留，安装确认会提示输入框不会覆盖保存配置。
3. 已安装设备选择运维区「修改热点接口与网关」。例如显示当前保存 `wlan0 / 192.168.0.1`，检测地址在 `br0`，推荐 `br0 / 192.168.0.1`。
4. 可重新检测或取消。填写接口与地址后，「确认修改」会再次检测，并显示停服与数据保留说明。取消不启动维护任务、不写入配置。
5. 提交后关闭页面不会取消后台任务。点击「查看配置修复结果」，核对任务 ID、结果、配置是否恢复、服务是否通过健康检查、认证是否关闭。
6. 成功后重新打开后台，检查配置，手动开启认证。未勾选服务设置确认项时，点击开启认证会跳转、聚焦并高亮该项一次；需要用户自行核对、勾选并保存。

网关在此指设备的热点侧 IPv4 地址，不是蜂窝网络的上游默认网关。不会修改宿主 WiFi 的 SSID、密码、加密或 OPEN 设置。

## 检测规则与兼容性

- 优先使用 Go 标准库接口/地址查询（Linux netlink），失败时回退到普通 `ip -4 addr show` 文本解析。不依赖 jq、Python、ip JSON 或额外设备运行时。
- 通过 `ip -4 route show table all` 识别默认路由上联；排除回环、点对点、已知蜂窝接口和已确认的上联。不能查询路由时明确告知，并不自动推荐。
- 浏览器 hostname 仅为线索；只有与系统真实 IPv4 相同、接口符合要求且唯一时才推荐。不按 wlan/br 名称认定热点；多候选展示列表，用户确认。
- 校验结果区分 `valid`、`invalid`、`unknown`。接口查询失败不等于接口不存在。无法完成验证时保留输入框，但需要恢复查询能力再安装或修复，不用“无法验证”冒充有效配置。
- Root 检测命令提供结构化 JSON，含 Protocol、Running、Saved、Bootstrap、Interfaces、Candidates、Recommended、Validation、SavedValidation、Warnings。Running 缺失表示无法确认运行态，不用保存值代替。
- 仅投影 LAN、Gateway、Enabled；不输出管理员哈希、恢复摘要、签名密钥、推送凭据或完整状态。检测临时程序由内嵌负载解压、校验 SHA-256 后执行，随后清理，不替换已安装服务。
- Android 版本和 SELinux 策略存在差异，标准库和 ip 均可能失败。兼容性依据：[AOSP iproute2](https://android.googlesource.com/platform/external/iproute2/)、[Go Android 接口查询权限问题](https://github.com/golang/go/pull/61089)。这些资料不代表完成 F50 实测。

## 身份验证与诊断

设备身份仍只接受当前配置接口的内核 ARP/邻居绑定。不接受浏览器自报 MAC，不跨接口放行，不开放非管理员完整后台。识别失败后检查接口，明确配置错误会给公开页面修复入口提示；详细接口和地址仅显示在 Root 检测及管理日志。配置有效而 MAC 未找到、系统查询失败/权限不足分别提示。

启动时配置错误记录告警，不因此直接退出；原有认证开启预检仍可关闭失效的认证并清理本插件规则。后台 MAC 限制继续生效。维护事务尚未提交期间，页面写操作、远程审批 POST 和本地管理员重置暂时拒绝，避免健康检查阶段产生随后被回退覆盖的新业务修改。

## 事务与锁顺序

1. 获取现有 update.lock 非阻塞排他锁，贯穿停止、备份、写入、启动、健康检查、回退。安装及在线更新也检查网络事务记录；更新事务未恢复时拒绝网络修复。
2. 校验输入、系统归属和状态结构，验证引导 JSON。损坏状态拒绝覆盖。创建独立 0700 备份目录与持久化 network-journal.json（stopping）。
3. service.sh stop-network 先设置 stopped 标志，按 PID 文件核验具体服务/supervisor 身份，停止 supervisor 与 worker。worker 按原生命周期采样、清理规则、恢复加速、保存最终状态；不使用 pkill 模糊匹配。维护期间等待 worker 正常退出，超时拒绝改配置，不强杀而丢弃最后一次采样。服务停止/重启可能中断连接。
4. 确认 supervisor 退出后，离线命令取得 service.lock，使用旧状态清理本插件 UFIG_ 规则并恢复标准 offload，将认证关闭。不会清空系统全局防火墙。
5. 维护进程再取得 service.lock，保存停止后的最新状态和引导备份。记录 backed_up 阶段后才替换任何目标网络字段。新进程先取得 service.lock 再读取状态，避免读取修改前的旧快照。
6. 重新验证接口地址后，只补丁修改 state.json 的 Config.LAN、Config.Gateway、Config.Enabled=false，以及 bootstrap.json 的 LAN/Gateway。其他 JSON 字段保留。临时文件 0600，写入 fsync、原子 rename、父目录 fsync。
7. 释放 service.lock，通过 start-network 启动。正常 start/boot 遇到未结束事务会走恢复，不会直接加载半完成配置。维护启动使用专用 worker 参数；正常 worker 遇到未结束事务拒绝启动。
8. 通过 0600 control.sock 连续三次检查 ready、实际 LAN/Gateway 和 Enabled=false。保存脱敏结果后删除并同步事务记录，完成提交。后台更新锁此时才释放。

未触及管理员账号、管理员设备权限、恢复密钥、setup.token、上网账号、信任/封禁、授权会话、配额、历史流量、限速、外观和推送配置。生命周期自身的采样、日志、内存登录会话和标准 offload 恢复仍按既有行为发生；不承诺网络连接不中断。设备恢复后可能需要重新登录。

## 失败与中断恢复

配置写入、只写一个文件、启动或健康检查失败：先再次停止并取得服务锁，再恢复备份的两个配置；原引导文件不存在时恢复为不存在。恢复状态的认证一律关闭，然后尝试启动并验证旧接口/网关的实际运行值。

中断或断电：下次 boot（存在开机接入时）或插件「启动服务」调用 --resume-network，读取事务阶段。stopping 阶段尚未替换目标配置，会先停止并建立最终快照；backed_up 阶段恢复原快照。原本已停服且无开机钩子的设备，在钩子建立前断电，需要通过插件「启动服务」触发恢复。均不会默认重新开启认证。

恢复失败保留事务、备份和诊断，不宣称成功；再次启动可重试。若服务无法停止，拒绝替换配置，此时认证未必已关闭，结果会明确报告。ServiceRunning 表示通过本地健康查询确认，不将单纯进程存在当作恢复成功。

设备上的记录位置：

- `/data/ufi-gate/network-journal.json`：未结束事务。
- `/data/ufi-gate/network-result.json`：脱敏结果，包含任务 ID、阶段、恢复/运行/认证状态。
- `/data/ufi-gate/network-repair.log`：维护命令输出。
- `/data/ufi-gate/network-backup-<任务 ID>/`：完整状态和引导备份，0700 目录、0600 文件。备份含用户敏感配置，只保留在设备；不要上传或放入发布包。

正常成功和已完成回退会移除事务记录，保留备份供排查。自动恢复不能替代可靠存储设备的断电写入保证；需要真机验证文件系统行为。

Root CLI（菜单优先；命令仅设备端 Root 可用）：

```sh
/data/ufi-gate/ufi-gate --dir /data/ufi-gate --network-inspect --network-host 192.168.0.1
/data/ufi-gate/ufi-gate --dir /data/ufi-gate --network-inspect --network-lan br0 --network-gateway 192.168.0.1
/data/ufi-gate/ufi-gate --dir /data/ufi-gate --network-repair --network-lan br0 --network-gateway 192.168.0.1
sh /data/ufi-gate/service.sh start
```

## F50 真机验收清单（本次尚未执行）

- Root/SELinux 下标准库接口查询、ip 文本回退、全部路由表查询可用性；br0 地址及手机邻居表归属；多地址/多接口时不错误推荐。
- wlan0 / 192.168.0.1 安装被明确拒绝，br0 / 192.168.0.1 通过；旧状态错误时普通升级保留配置且明确引导修复。
- 运行及停止状态均能从插件完成修复；旧 supervisor 和 worker 真正停止，未误杀维护进程；旧规则清理先于配置替换。
- 对比修复前后管理员、恢复密钥可用性、设备权限、setup.token、授权/信任/封禁、账户、配额、最终流量、限速、外观及推送配置。
- 修复后手机完成初始化/登录，其他非管理员仍无法访问完整后台；MAC 随机化后的既有恢复流程正常。
- 模拟存储满、写入失败、端口占用、启动失败、健康检查失败；在停止、备份、单文件写入、启动和提交前分别中断/断电，验证恢复策略、结果与认证关闭。
- 更新任务与修复互斥；修复期间点击普通启动/停止/卸载不造成并发写入。重启后的开机恢复路径与标准 offload 恢复正确。
- 修复后手动开启认证，验证实际 IPv4 准入、DNS、流量、配额、IPv6 阻断及厂商加速；确认宿主 SSID/密码/OPEN 完全未改。
- 手机宿主浏览器的检测程序上传、gzip 解压、Root Shell 超时、断网后返回插件查看结果；ARM32/ARM64 分别实测。

本地浏览器、模拟执行器和交叉编译不能替代这些设备验收；Linux race、QEMU 和 Android supervisor 真实进程行为须在相应环境验证。
