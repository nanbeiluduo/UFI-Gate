# 远程审批（v1.1.9 起）

UFI-Gate 提供独立审批入口和后台设置，不提供公共穿透服务器，也不会自动建立隧道。是否使用免费或付费穿透、服务器及域名，由用户自行决定。

## 连接方式

管理员手机 → 自备 HTTPS 公网地址 → 加密隧道 → 随身 WiFi 本机 `127.0.0.1:8091` → 签名审批确认页面。

穿透客户端必须运行在随身 WiFi 同一设备上。当前只监听 IPv4 回环地址 `127.0.0.1`，不支持直接从另一台局域网设备连接审批端口。客户端是否兼容 Android ARM32/ARM64、固件权限、内存与开机常驻，需要自行验证；穿透程序不包含在 JS 安装包内。

## 设置步骤

1. 将服务更新到 v1.1.9，在管理后台进入「消息推送」，配置飞书、企业微信、通用 Webhook 或 SMTP，并保存。先使用「测试推送渠道」检查消息送达；这个旧测试的审批按钮不是有效审批。
2. 准备固定 HTTPS 域名，例如 `https://approve.example.com`，并在设备上安装、配置穿透客户端。公网 TLS 必须使用浏览器信任的有效证书；远程服务器到客户端之间使用加密连接。本机回环段使用 HTTP。
3. 在「远程审批 · 自备穿透服务」勾选启用，填写公网审批地址与本机端口（默认 8091），保存。仅接受 HTTPS 根地址，可带端口，不接受路径、查询参数、片段或 URL 用户名密码。
4. 将该域名转发到 `http://127.0.0.1:8091`（修改端口后相应调整）。保持原始路径、查询参数和 POST 表单，不添加路径前缀；禁止缓存审批页面。无需转发 8081 后台、8090 门户或宿主 Root Shell。
5. 点击「发送远程审批测试」，关闭手机 WiFi，使用移动网络打开消息中的任一按钮，再点击「确认测试」。测试有效期 5 分钟，只能确认一次，不会给任何设备放行；重新生成会使之前的测试链接失效。发送至少间隔 30 秒，失败原因见运行日志。
6. 用第二台访客设备提交真实上网申请。管理员通过手机流量打开消息并确认同意/拒绝，验证设备实际联网行为。

填写公网地址不代表隧道已建立。后台无法仅凭一次本机请求判断运营商外网是否可达，因此以管理员手机流量测试为准。

## 对接约定

| 项目 | 规则 |
| --- | --- |
| 本地目标 | `http://127.0.0.1:8091`，端口可修改 |
| 公网地址示例 | `https://approve.example.com` |
| 正式审批 | `GET /approve?token=...` 显示确认页；`POST /approve` 提交表单 |
| 专用测试 | `GET /approve-test?token=...`；`POST /approve-test` 确认测试 |
| 页面资源 | `GET /style.css` |
| 其他路径 | 404，不提供管理 API、登录、配置或 Root Shell |

表单字段为 `token`、可选 `reason`（正式审批备注上限 1000 字节）；测试不使用备注。不要修改或伪造 token，也不要在代理日志中保存完整审批 URL、查询参数或请求体。保留浏览器 Origin；有 Origin 的 POST 必须匹配配置的公网地址。服务不信任 `X-Forwarded-For` 等头来授予管理员权限。

frp 用户可把自有服务端的转发连接指向上述本机目标，并在公网入口提供 HTTPS；Cloudflare Tunnel 等工具可把自有域名路由到上述 HTTP 目标。具体配置按所用工具版本与供应商说明操作。UFI-Gate 不绑定服务商，不收取穿透费用，也不保证第三方网络可用性。

## 行为与边界

- 默认关闭，旧配置无需迁移；启用后新发出的审批消息使用远程地址，关闭后恢复原有 `PublicBase` 或网关局域网地址。已有消息不会被自动改写。
- 保存后立即生效，无需重启；端口冲突会拒绝保存并保留原设置。启动时若审批端口无法绑定，主服务继续运行并记录错误，修正端口后重新保存即可。
- 正式链接沿用 HMAC 签名、申请有效期和单次处理检查；持有链接即可执行对应审批，请勿转发给访客。GET 仅展示，POST 才处理。
- 独立入口每分钟全局最多 120 次请求（含页面资源），超限返回 429；不依赖可伪造的代理 IP 请求头。
- 后台 8081 的管理员设备限制保持不变。远程审批不授予后台权限，不开放恢复密钥或账号管理接口。
- 停用远程审批会关闭监听；管理员重置后、尚未重新初始化时，独立入口拒绝请求。测试票据只保存在内存，服务重启即失效。
- 设备离线、断电或隧道中断时无法远程审批；没有云端离线审批队列。访客上网流量不经过此审批隧道。

## 排查

- **消息能收到但链接打不开**：核对消息是否仍是旧的局域网链接、隧道在线状态、HTTPS 证书、DNS，以及目标是否为本机审批端口。不要转发受 MAC 限制的 8081。
- **404**：确认已启用远程审批、完成管理员初始化，转发没有增删路径。
- **403**：公网访问域名与后台所填地址不一致，或代理改写了 Origin。
- **400**：链接被修改、已过期或已处理；测试链接在重启、重新生成或配置变更后也会失效。
- **429**：等待一分钟后重试，并检查是否有自动探测频繁请求该入口。

自动化测试只验证演示服务与接口，不代表已完成飞书实际送达、第三方隧道或随身 WiFi 真机验收。
