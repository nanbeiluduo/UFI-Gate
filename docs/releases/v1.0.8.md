# UFI-Gate v1.0.8

WiFi 踢线修复：纠正 hostapd 控制协议，在清除会话或封禁设备时尝试真正断开该设备的 WiFi 连接一次。

## 修复与调整

- **修正连接方式**：将 hostapd 控制口连接由 Unix 流式连接改为 Unix 数据报，并绑定临时客户端地址以接收命令回复，完成后清理临时 socket。
- **修正踢线命令**：使用标准 `DEAUTHENTICATE <MAC>` 命令，替换原来的 `DEAUTH`。
- **扩大控制口探测范围**：通过 `/proc/net/unix` 和常见 Android / Linux hostapd 目录查找控制接口，支持文件系统及抽象 Unix socket。
- **确认目标设备所在接口**：先发送 `STA <MAC>` 查询，确认设备属于该热点接口后再发送断开命令，避免向其他热点接口盲目发送。
- **严格检查结果**：只有收到 `OK` 才记录 hostapd 已接受单次断开命令。失败日志区分未发现控制口、未查到设备、通信错误、超时及命令失败，不再统一提示「未找到控制口」。
- **演示模式跳过真实踢线**：本地演示不操作 WiFi 设备，仅记录提示。

## 使用与行为

在后台「设备管理」中点击「清除会话」或「封禁」，会继续执行原有联网授权操作，并调用修复后的单次踢线逻辑。

本次实现的是断开一次 WiFi 连接，不加入 WiFi 接入层黑名单，也不持续阻止手机重连。手机可能随后自动连接热点；是否自动重连由手机系统和用户设置决定。清除会话后，设备仍需按门户策略重新认证。

踢线失败不会阻止清除会话或封禁操作。设备可能仍保持 WiFi 连接，但无法按原有授权继续上网。后台日志可用于区分联网授权变更与实际踢线命令的执行结果。

## 固件兼容性

真正踢线依赖固件提供可访问的 hostapd 控制接口及相应权限。Root 权限不代表所有设备都开放此接口；仅通过 Android HAL 或厂商私有接口管理热点的设备，可能仍需针对固件适配。

日志中的「hostapd 已接受单次断开命令」表示控制接口返回成功，不代表手机会保持离线，也不等同于已完成真机断连验证。

## 更新

本次新增 `kick.go`、`kick_test.go`，并修改 `main.go`。需要重新构建并安装对应架构的新版插件；仅上传源码或刷新后台页面不会更新设备上的踢线逻辑。

导入对应架构的新包，保存并刷新，打开「UFI-Gate 网闸」，先检测环境，再安装 / 更新服务。保留 `/data/ufi-gate` 状态目录以保留账户、配置和流量历史。运行中升级会暂时恢复网络并关闭认证，完成后核对配置并重新开启。

## 验证边界

- 已通过本地可运行的后端测试，新增测试覆盖目标接口选择、标准命令发送、成功回复校验及失败结果处理。
- 已新增 Unix 数据报集成测试，验证请求、回复和临时 socket 清理；该测试在 Windows 上跳过，尚未在本地 Linux 环境执行。

- 已完成 Linux ARM32 / ARM64 插件打包。
- 尚未完成设备端真机验证，需在目标设备上检查控制口可用性、踢线日志和手机实际断连表现。
