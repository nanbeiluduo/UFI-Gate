# UFI-Gate v1.0.9

联网授权管理调整：移除主动断开 WiFi 的尝试，保留「清除会话」撤销联网授权、要求设备重新认证的功能。

## 调整

- **清除会话**：取消设备当前联网会话和永久信任。认证服务开启时，设备需重新认证才能恢复正常上网；已有封禁或配额限制仍然保留。
- **封禁设备**：继续阻止设备联网，需管理员解除，不再额外尝试断开 WiFi 连接。
- **移除 hostapd 踢线逻辑**：删除控制口探测、设备查询及断开命令调用，操作不再等待 hostapd 回复，也不会新增对应的踢线超时日志。历史日志不受影响。
- **同步文档**：更新 README 与安装指南，明确联网授权撤销和手机认证提示的实际行为。

## 使用行为

在后台「设备管理」中点击「清除会话」后，设备可以继续连接 WiFi，但原有联网授权已被撤销，需要重新认证。本版本不主动让手机断开热点，也不要求用户手动重新连接 WiFi。

用户已反馈，在其测试的苹果及安卓手机上，清除会话后会自动出现需要认证的提示。是否自动弹出、何时弹出仍由手机系统决定，插件不保证所有设备都表现一致。未自动弹出时，可手动打开 `http://热点网关:8090/` 进入认证门户。

上述网络准入限制在认证服务开启时生效。免认证白名单继续按原有规则处理，清除会话不会清空流量统计、配额设置或独立限速设置。

## 与 v1.0.8 的区别

v1.0.8 尝试通过 hostapd 控制接口断开设备 WiFi，但部分固件存在控制接口或回复权限兼容问题。本版本取消该附加动作，以撤销联网授权和重新认证作为设备会话管理方式，不再依赖 hostapd 踢线能力。

## 更新

本次修改 `main.go`、`README.md` 和 `docs/INSTALL.md`，并删除 `kick.go`、`kick_test.go`。同步源码时应同时删除这两个旧文件。

需要重新构建并安装对应架构的新版插件；仅上传源码或刷新后台页面不会更新设备上的服务逻辑。

导入对应架构的新包，保存并刷新，打开「UFI-Gate 网闸」，先检测环境，再安装 / 更新服务。保留 `/data/ufi-gate` 状态目录以保留账户、配置和流量历史。运行中升级会暂时恢复网络并关闭认证，完成后核对配置并重新开启。

## 验证边界

- 已通过本地可运行的后端测试。
- 本地测试在 Windows 环境下通过临时覆盖绕过 Linux 文件锁，排除依赖 Unix 文件权限的 `TestPersistenceAndPermissions` 后，其余测试通过；正式源码保留 Linux 文件锁逻辑。
- 已完成包含本次调整的 Linux ARM32 / ARM64 插件打包。
- 用户反馈的苹果及安卓认证提示行为来自此前版本的实际使用，本次调整后的安装包尚未完成设备端真机验证。

详细说明见 [安装与管理指南](../INSTALL.md#清除会话与封禁)。
