# UFI-Gate v1.1.1

修复国内网络环境下更新检查失败的问题：新增多个公共 GitHub 加速镜像作为下载回退，按"直连 GitHub → 镜像列表"顺序依次尝试，任一源成功即继续安装。

## 问题

v1.1.0 在国内随身 WiFi 网络下点击「检查更新」时，能成功从 `api.github.com` 拉取 release 标题与说明，但下载 `update.json` 时 `dial tcp <github.com IP>:443 i/o timeout`，后续更新包同样无法下载。原因是 `github.com/releases/download/...` 在国内网络下可达性不稳定，且会再 302 到 `objects.githubusercontent.com`（Fastly CDN）。

## 改动

- 拉取 `update.json`、`update.json.sig` 与更新包 `UFI-Gate-<ver>-<arch>-update.tar.gz` 时，按候选列表依次尝试：直连 `github.com` → `ghfast.top` → `gh-proxy.com` → `ghproxy.net` → `mirror.ghproxy.com`。
- 任一候选返回内容即停止；全部失败时在错误提示中列出所有候选的失败原因，便于排查。
- 镜像仅作为传输通道：`update.json` 仍必须通过内置 Ed25519 公钥验签，更新包仍必须对得上清单中的 SHA-256 与大小，镜像被投毒或篡改都会被拒绝，不降低安全性。
- dial 超时沿用现有 6 秒，单个镜像卡住不会长时间阻塞，可快速切到下一个候选。

## 升级

v1.1.0 用户在后台「更新管理」直接点「检查更新」即可看到本版本；若直连仍超时，会自动走镜像完成下载与安装。安装流程短暂停服并关闭认证，完成后重新登录、核对设置再手动开启认证；不要删除 `/data/ufi-gate`。
