# UFI-Gate v1.2.0

新增热点接口与网关检测、安装前校验及插件配置修复入口，帮助处理接口配置错误导致的管理员初始化失败；开启认证时增加服务设置确认项的跳转与高亮引导。

## 热点接口检测与安装校验

- **统一检测规则**：「检测环境」与安装前校验共用 Go 服务的检测逻辑，展示服务实际运行配置、已保存配置、安装引导配置，以及系统接口状态、IPv4 地址与前缀、候选接口和推荐理由。
- **核实后推荐**：优先推荐持有当前访问的本机 IPv4 管理地址的接口；浏览器地址必须与设备真实地址核对，不根据 `wlan`、`br` 等名称直接认定热点接口。无法可靠区分多个候选时，由用户选择。
- **安装前验证**：检查接口名称、接口是否存在及启用、是否适合作为热点，以及所填 IPv4 地址是否属于该接口。明确错误会阻止安装；系统查询失败或信息不完整时显示「无法验证」，保留手动输入能力，需恢复验证后再继续。
- **明确配置来源**：已有状态配置继续保留。安装器会提示，修改输入框或安装引导配置不会自动覆盖已保存的热点接口与网关，普通升级不会静默切换接口。

例如，中兴 F50 的 `192.168.0.1/24` 位于 `br0`，但填写了 `wlan0` 时，将提示：

> 192.168.0.1 当前配置在 br0，而不是 wlan0。请检查热点接口。

这里的网关是随身 WiFi 的热点侧 IPv4 地址，不是蜂窝网络的上游默认网关。检测不依赖设备安装 jq、Python 或支持 JSON 输出的完整 iproute2。

## 插件内修复接口与网关

- **新增「修改热点接口与网关」**：位于插件运维区域，无需进入 UFI-Gate 后台，也支持已安装但服务未运行的设备。
- **显示配置差异**：读取实际运行、保存和引导配置，展示检测结果与建议值，支持「重新检测」「取消」「确认修改」。未安装或旧服务缺少专用命令时给出明确提示，不直接编辑未知格式的状态文件。
- **确认后执行**：短暂停止服务、恢复原有网络准入，再修改 UFI-Gate 的接口和网关。保留管理员、管理员设备权限、恢复密钥、初始化凭证、上网账号、设备记录、信任与封禁、授权会话、配额、流量、限速、外观和推送设置。
- **备份与恢复**：与安装、更新共用互斥锁；待服务停止并保存最终状态后备份，通过事务记录协调状态与引导两个文件的写入。写入、启动或健康检查失败时尝试恢复原配置；中断事务可在后续启动时恢复。
- **结果可查询**：新增「查看配置修复结果」，显示任务结果、配置是否恢复、服务健康状态、认证关闭状态，以及备份和诊断位置。页面关闭后维护任务继续运行。

修复成功或完成回退后，认证保持关闭，需要检查后手动开启。若服务无法安全停止，会拒绝替换配置；恢复未完成时保留事务与诊断，不将失败显示为成功。

停止、重启可能造成网络连接中断或需要重新登录。本功能不修改 UFI-TOOLS 自身的 SSID、密码、加密或 OPEN 等 WiFi 参数，也不删除状态目录或清空系统全局防火墙。

## 初始化诊断与开启认证引导

- **更明确的设备识别错误**：区分接口配置错误、配置有效但找不到当前设备 MAC，以及系统查询失败或权限不足。可确定的配置错误会引导用户进入插件菜单的「修改热点接口与网关」，避免只提示反复重连 WiFi。
- **保留身份验证边界**：仍只使用配置接口上的内核 ARP／邻居绑定，不接受浏览器自报 MAC，不跨接口随意放行，不因初始化失败开放非管理员访问完整后台。
- **启动诊断**：错误接口配置会记录明确告警，不因新增诊断直接退出服务；原有规则清理和恢复入口继续保留。
- **跳转并高亮确认项**：未勾选「已核对接口、加速设置，并准备好 Root 恢复通道」时点击开启认证，会进入「服务设置」、聚焦并高亮该项一次。用户须自行核对、勾选并保存，系统不会自动勾选或开启认证。

## 安装与维护调整

- 移除安装器通过 `pkill -f ufi-gate` 模糊匹配清理进程的步骤，避免误杀更新或配置维护任务。
- supervisor 按 PID 文件和具体进程身份检查服务。配置维护期间等待 worker 正常退出；超时拒绝改配置，不强制结束尚未完成最终保存的 worker。
- 服务先取得锁再读取状态，避免维护期间载入旧配置。事务提交前暂时拒绝页面业务写入、远程审批提交和管理员重置，防止新操作随后被回退覆盖。

## 升级与使用

本次包含 Go 服务、启动脚本、管理页面和插件菜单修改。**需要更新服务，并替换 v1.2.0 对应架构的 JS 插件**；只在独立后台更新服务，不会更新 UFI-TOOLS 保存的插件菜单。

1. 根据设备架构下载 `UFI-Gate-1.2.0-arm32.js` 或 `UFI-Gate-1.2.0-arm64.js`，不要同时导入两种架构。
2. 替换旧插件条目，保存并刷新，先运行「检测环境」，核对接口和热点侧 IPv4 地址，再安装／更新服务。
3. 如果已有保存配置错误，普通升级会保留它。更新服务后使用「修改热点接口与网关」明确确认修复，不要依靠修改安装输入框纠正旧状态。
4. 查看修复结果，重新打开后台，检查配置后手动开启认证。

不要删除 `/data/ufi-gate`。设备上的事务备份包含敏感配置，请留在设备上，不要上传到 GitHub 或放入发布包。

详细操作、失败恢复与真机验收清单见 [热点接口与网关修复指南](https://github.com/nanbeiluduo/UFI-Gate/blob/main/docs/NETWORK_REPAIR.md)。
