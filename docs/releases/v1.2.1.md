# UFI-Gate v1.2.1

修复旧用户可能依靠历史确认值跳过开启认证引导的问题：每次手动开启认证均需本次勾选服务设置确认项，并保留自动跳转、聚焦与高亮引导；README 新增参考文档索引。

## 开启认证确认修复

- **新老用户使用相同规则**：不再仅依赖已保存的 `Verified` 历史值。每次手动开启认证，都需要在本次页面操作中勾选「已核对接口、加速设置，并准备好 Root 恢复通道」。刷新页面、重新登录，或关闭认证后再次开启，均需重新确认。
- **修复取消勾选未保存时仍可开启的问题**：页面当前未勾选时，即使设备保存的历史确认值为真，也不能开启认证。引导不会重新渲染并覆盖当前未勾选状态或其他未保存的服务设置。
- **保留跳转与高亮**：未完成确认时点击「开启认证」，会进入「服务设置」、滚动到确认项、聚焦并高亮一次。不会自动勾选、自动保存或自动开启认证。
- **区分勾选与保存**：如果设备尚未保存确认，或页面上的热点接口、网关有未保存修改，需要先保存设置再开启；已保存的历史配置仍不能替代本次勾选。
- **服务端同步校验**：开启请求须同时满足设备已保存确认和本次请求明确确认。旧页面或缺少本次确认标记的请求会被拒绝，并返回确认引导错误；更新后请刷新管理页面。
- **关闭认证不受影响**：未勾选确认项也可以关闭认证、恢复原有网络准入。取消勾选本身不会自动停止正在运行的认证服务。
- **修复确认值保存一致性**：认证开启且使用第三方验证码时，保存服务设置不再忽略用户取消勾选的值。

本次调整针对后台的手动开启操作，不改变既有开机认证恢复策略，不清除管理员、设备、账号、配额、流量或其他业务数据。

## 升级与使用

已有用户可通过独立后台更新服务。此次修复涉及服务端和内嵌管理页面，更新后请刷新页面；无需为本次确认修复单独替换已有的 v1.2.0 插件菜单。首次安装可使用对应架构的 v1.2.1 JS 安装包。

开启认证前，进入「服务设置」，核对接口、网关、加速设置和 Root 恢复通道，勾选确认项；配置有修改时先保存，再点击开启认证。不需要删除 `/data/ufi-gate` 或重新初始化管理员。

如自行调用管理 API，`POST /admin-api/toggle` 开启认证时需提交 `{"Enabled":true,"Confirmed":true}`，且设备保存的 `Verified` 必须为真。关闭仍可提交 `{"Enabled":false}`。此确认标记不替代原有登录、管理员设备权限及来源检查。

## 验证范围

- Windows 本地完整 Go 测试与 `go vet` 通过。新增测试覆盖历史确认值不能单独开启、本次确认与已保存确认的组合校验、未确认仍可关闭，以及第三方验证码场景下取消勾选的保存行为。
- 浏览器回归覆盖旧配置已确认为真时仍需本次勾选、取消勾选但未保存、保留未保存接口输入、勾选后开启、关闭后重新引导、未保存确认时阻止开启及刷新后重新确认。
- 原有热点配置修复交互与门户认证流程回归通过，门户完成 30 项页面检查，浏览器错误为 0。
- ARM32／ARM64 本地构建与 24 个安装器场景通过，两种 JS 均低于宿主 5 MiB 限制；JavaScript 语法检查通过。本地构建未使用正式签名私钥，正式发布仍由现有工作流签名构建。
- 本次未进行 F50 或其他 Android 真机验收，未在本地执行 Linux race／QEMU；浏览器演示和本地测试不代表真实设备验收已完成。
